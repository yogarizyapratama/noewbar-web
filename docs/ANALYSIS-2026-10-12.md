# Analisa Proyek Noewbar CS Pro

**Tanggal:** 12 Oktober 2026
**Metode:** pembacaan kode + perintah nyata (bukan pembacaan dokumen saja).
**Catatan:** dokumen ini adalah hasil analisa, bukan klaim "semua hijau". Bagian yang tidak bisa diverifikasi ditandai eksplisit.

## 1. Identitas Nyata vs Dokumen

Dokumen di `docs/` (`AI-CONTEXT.md`, `ARCHITECTURE.md`, `AUDIT-REPORT.md`) sudah **tertinggal jauh** dari isi repo. Angka di bawah diambil dari filesystem, bukan dari dokumen.

| Aspek | Klaim dokumen | Kenyataan (`find`/`wc`/`git`) |
|---|---|---|
| Git | **BUKAN git repo** (`git log` -> 128) | **Sudah git repo**: 42 commit, remote `github.com/yogarizyapratama/noewbar-web.git`, working tree bersih |
| Skala | 43 file TS/TSX, 9.901 LOC | **80 file TS/TSX, 31.823 LOC** (3.2x) |
| API route | 12 | **17** |
| Tabel/Model | 11 tabel | **13 model** (+ `products`, `websites`) |
| Halaman | 3 halaman | + storefront `store/[slug]`, superadmin console |
| Node | 22.23.3 | shell default **v18.20.3** (butuh >=20.9.0, `.nvmrc` = 22.23.3) |
| Database | PostgreSQL lokal `:5433` | `.env` menunjuk **host Tailscale `100.67.219.105:5432/noewbar_pro_db`**; PG lokal `:5433` **tidak punya** database `noewbar_pro_db` |

**Fitur yang ada di kode tetapi tidak ada di dokumen arsitektur** (semuanya >700 baris, jadi bukan tambahan kecil):

- `src/app/dashboard/panel-website-builder.tsx` (3.959 baris) + `website-inspector.tsx` (1.602) + `src/lib/website/` + `api/websites` : **website builder drag-and-drop per tenant**.
- `api/products` + `api/products/upload` + `panel-products.tsx` (938) : produk kini tersimpan di PostgreSQL (`products`), bukan hanya Google Sheets.
- `panel-promos.tsx` (744) + `toolHitungPromoBundling` : bundling/voucher per tenant.
- `toolRekomendasiUkuran`, `toolCekJadwalPengiriman`, `toolRekomendasiAlternatif` : tool AI tumbuh dari 5 ke **9+**.
- `api/simulator`, `panel-simulator.tsx` (531), `api/knowledge` + knowledge-store, superadmin WhatsApp connect/broadcast, subscription enforcement (`subscription-guard.ts`).
- `tests/` (unit/api/e2e) : suite baru di luar `scripts/gates.ts`.

**Kesimpulan §1:** kode berjalan lebih cepat daripada dokumentasi. `AGENTS.md` bagian 0.2 dan `AI-CONTEXT.md` bagian 1 sekarang **salah secara faktual** dan menyesatkan agen berikutnya (aturan "verifikasi lewat filesystem, jangan git" sudah usang).

## 2. Yang Terbukti Benar (dari kode, bukan dari klaim)

Ini yang saya baca langsung dan sesuai dengan aturan domain:

- **Fail-closed env benar-benar ditegakkan.** `src/lib/env.ts:23,29,30,55` → `DATABASE_URL`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `WHATSMEOW_SECRET` memakai `.min(1)` **tanpa default**. Temuan S-1 (kredensial hardcoded) memang sudah hilang.
- **Webhook tidak bisa dipanggil anonim.** `wa-webhook/route.ts:55-62` mengembalikan `false` bila secret kosong, lalu 401. Guard-nya hidup, bukan dead code.
- **Idempotency lewat constraint, bukan baca-lalu-tulis.** `wa-webhook/route.ts:90-106` menangkap `P2002` dan mengembalikan `duplicate_delivery`.
- **Tenant dari `instance_key`, bukan dari payload pembeli.** `route.ts:109-118` (`waInstance.findUnique` -> `tenant`), sehingga pembeli tidak bisa memalsukan tenant.
- **Disiplin kode tinggi.** 0 `TODO`/`FIXME`/`HACK` di `src` + `scripts`; 0 `console.log` di `src`; hanya **7** `as any`/`@ts-ignore` di 31.823 LOC.
- **Arsitektur inti sesuai dokumen.** Dua state machine (`orders/state.ts`), `assertFulfilmentAllowed`, `findUnbackedPrices` (`orchestrator.ts:76`), `knowntool` allowlist, scheduler proses terpisah.

`src/app/api/playground/route.ts` (`DEFAULT_PLAYGROUND_CATALOG`) sengaja menyajikan

### 🟠 N-2: Suite E2E memakai data demo, dan "PASS" bisa berarti retry

`tests/e2e/user-flows.test.ts`:
- `:10-24` `demoCatalog` hardcoded (Unsplash + harga `95000` + kategori karangan);
- `:36-41` data pembayaran palsu (`bankAccountNumber: "1234567890"`);

Dampaknya: suite ini melaporkan "100% green" sambil mem-*bypass* justru guard `findUnbackedPrices` (karena harga datang dari data uji, bukan dari tool) dan menyamarkan flakiness yang sudah dikenal (Gate 3 / C-1). Ini bertabrakan dengan aturan bukti di `AGENTS.md` bagian 2 ("Tidak boleh memfabrikasi output uji").
**Perbaikan yang benar:** pakai katalog nyata dari fixture tenant yang dibuat lalu dibersihkan, dan laporkan `retries_used` supaya percobaan ke-2/ke-3 terlihat.

### 🟡 N-3: Data contoh di website builder

`panel-website-builder.tsx:175-183` dan `:2557` menyimpan daftar gambar Unsplash berlabel ("Skincare Glow Serum", dst) sebagai pilihan media. Sebagian masih dapat dibenarkan sebagai galeri contoh, tetapi bila tombolnya mengisi section secara otomatis maka itu data contoh yang masuk ke situs tenant (melanggar A7). Perlu keputusan pemilik produk: galeri contoh vs konten otomatis.

### 🟡 N-4: Dokumentasi drift adalah risiko operasional, bukan kosmetik

`AGENTS.md` menginstruksikan agen berikutnya untuk **tidak memakai git** dan menyebut 11 tabel/12 route. Agen yang mematuhi instruksi itu akan salah menilai apa yang aman diubah (mis. `products` dan `websites` sudah jadi tabel produksi yang tidak disebut di A9).

## 5. Penilaian

**Kekuatan.** Fondasi arsitekturnya kuat dan konsisten dengan niat produknya: zero-custody, satu gerbang menuju `VERIFIED`, penegakan aturan di kode bukan hanya prompt, fail-closed pada input tidak tepercaya, idempotency berbasis constraint. Disiplin kebersihan kode termasuk tinggi (nol TODO, nol `console.log`, 7 escape hatch di 31.8k LOC). Cakupan produk jauh melampaui dokumen: storefront, website builder, promosi, knowledge base, pengiriman, superadmin.

**Risiko utama.** (1) **Integritas pembuktian** : suite uji sendiri memakai data karangan dan menyembunyikan flakiness lewat retry, sehingga "hijau" tidak lagi otomatis berarti "benar"; ini risiko paling serius karena menghapus nilai gate. (2) **Dokumentasi drift** : `AGENTS.md`/`AI-CONTEXT.md` salah soal git, jumlah tabel, dan jumlah route; agen atau developer berikutnya akan tersesat. (3) **Dua file monolitik** (`panel-website-builder.tsx` 3.959, `superadmin/page.tsx` 3.244) melawan aturan `AGENTS.md` bagian 10 yang justru mewajibkan panel kecil per tab. (4) **Dependensi DB produksi remote** untuk verifikasi, sementara dokumen menyatakan lokal.
